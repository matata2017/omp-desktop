# DSH 性能研究设计（待产品边界确认）

本文件设计测量与决策，未选择最终重写架构。详细证据协议见 research/method-and-proof.md。

## 边界

沿用户操作到可见结果的关键路径分层：界面提交/渲染、宿主与插件、agent 调度、模型网络、工具子进程、持久化/恢复。记录每层进出时间、请求归属、排队及复制字节，重叠 span 不直接求和。

## 候选与因果对照

A：固定官方/本地原实现基线。B：相同语言下消除实测重复工作。C：只将被证实的热点换为 Rust，保持协议和输入。D：Rust 核心重构，明确改变的所有权与持久化边界。全量重写仅在 D 无法满足目标且完整兼容成本已确认时进入比较。每个候选报告相对 A 与前一候选的独立增益，不能混淆语言、算法、功能删减与构建参数收益。

## 正确性契约

状态归属唯一、请求终态唯一、取消/副作用提交边界明确、已确认持久化可恢复、重连序列无遗漏且不重复应用、队列与资源生命周期有界。参考实现差分用于发现差异，明确需求与独立判定器负责裁决。

## 决策变量

第三方 JS/Cordis 插件是否必须原样运行尚待用户选择。若必须兼容，评估保留受控 JS 插件宿主的成本；若允许迁移，按必要插件逐项重建协议和行为契约。两条路线的功能负载不同，必须分别说明，不能冒充公平语言性能比较。

## 当前限制

无 DSH 运行 trace、无 baseline 成绩；源码版本与已安装二进制尚未绑定。不得把候选架构当作性能结论，不启动实施。
