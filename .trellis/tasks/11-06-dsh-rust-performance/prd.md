# DEEPSEEKHARNESS Rust 性能研究

## Goal

评估重做 DEEPSEEKHARNESS 是否能在不损失必要行为的前提下，更快、更省内存、更可靠。用户要求更深入的研究，而非扩大功能；Rust 是候选技术，不是预先证明的性能结论。已获创建任务与规划授权，未获产品代码实施授权。

## Requirements

- R1：解释专家会额外检查的关键约束：收益上限、状态所有权、进程生命周期、兼容性成本和可证伪条件。
- R2：从原始源码、二进制、协议事件、OS trace、堆/分配、磁盘数据形态与失败案例取证；整理文档仅作导航。
- R3：给出定位瓶颈、区分因果、比较候选方案的方法与工具；明确每项工具回答的问题。
- R4：定义不依赖作者口头判断的性能与正确性证据，包括确定性回放、独立判定器、真实端到端复测和第三方复现。
- R5：分别评估保留实现优化、Rust 热路径替换、Rust 核心重构、全量重写；不预定赢家，不增加新功能。

## Acceptance Criteria

- AC1（R1/R5）：明确 Rust 语言能力与系统端到端收益的区别，给出有条件收益上限及放弃重写的条件。
- AC2（R2）：源码结论可追溯到文件/行与固定提交；事实、假设、提案、未测项分别标记。
- AC3（R3）：测量方案包含冷/热态、长会话、并发、取消/恢复；报告 CPU、进程树内存、尾延迟及质量口径，控制模型和输入。
- AC4（R4）：正确性先于速度；会话隔离、事件次序、终止/恢复、持久化及必要插件能力有独立判定方式；性能门槛在实现前冻结。
- AC5（R1–R5）：本轮完成可审阅的方法与证据设计，不能声称已测出 DSH 瓶颈、速度提升或证明重写正确。

## Out of scope

- 本轮不改 DSH/Romp 产品代码，不启动重写，不安装更新或终止用户进程，不批量读取私人会话和凭据。
- 不把 Rust 占比、模块数或功能数量作为成功指标；不迁移整理文档里的全部历史需求。
