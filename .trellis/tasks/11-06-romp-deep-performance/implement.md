# 后续执行计划（未获实施批准）

1. 先决定进程隔离/常驻服务的产品风险取舍；固定独立 review 分支、构建类型、二进制哈希及输入。
2. 修正测量脚本的本次日志边界、可用终点、进程树归属和原始样本输出；不改动产品行为。
3. 采 cold/warm 启动到可用、长会话、多 tab、流式、取消/恢复、退出/强杀的 WPR/ETW 与事件时间线；profiling 运行与性能成绩分离。
4. 用固定回放和负控验证判定器；冻结性能门槛、样本设计和否决规则。
5. 仅实现一个证据最强的候选；先做同语言减少重复工作，再评估 Rust 热路径或生命周期变化。
6. 差分事件日志、进程树审计、故障注入、外部效果断言；任何正确性退化阻断性能通过。
7. 随机交错 A/B、多批次与第二机器复现，发布原始数据、分析程序和失败样本。

## 撤回与限制

本轮无产品代码变更；未来实验使用独立配置和脱敏 fixture，不原地覆盖用户会话数据；性能结论必须来自固定构建的原始 trace。
